> 轮次：老板第 20 轮（2026-09-20）｜设计工具：Pencil（`pencil-new.pen`）
> 素材生成：Agnes `agnes-image-2.5-flash`，1K 方图，白底抠除
> 生成脚本：`.workbuddy/ref/vessel_v3.py`｜建板脚本：`.workbuddy/ref/pencil_v3_popups.js`（Update/Replace 建树版）、`pencil_v3_boards2.js`、`pack_v3.py`（打包）

## 1. 这一版为什么重做（老板第 20 轮口径）

上一版（`2026-09-20-add-food-popup`）给**每种食物各画一张图、图里放对应食物**，老板判定「思路不对」：
器具模板一共就这么多规格，与其给每种食物配图，不如**每种规格只做一张通用器具图，靠缩放表达份量大小**。
用户要的是「一眼看懂这一份有多大」，不是「这张照片拍得有多精致」。

本轮六条口径与落点：

| # | 老板口径 | 落点 |
|---|---|---|
| 1 | 天平砝码想法很好（小/中/大份 → 1/2/3 个） | `pot`（按份）改用砝码图 ×1/×2/×3，弹窗⑥ |
| 2 | 1个/1片/1串也必须生图，要实拍风，拒绝图标 | 白瓷球（个）、白瓷方片（片）、竹签串（串）三张实拍图 + 弹窗⑦⑧⑨单档大图 |
| 3 | 没有 15 种要生成，里面有重复的 | 18 个 vesselTpl key → **14 张器具图 + 4 张餐次图**，见 §2 |
| 4 | 奶茶甜度做成 10 格电量 | 弹窗①甜度区改 10 格电池条，无糖 0 格亮 / 全糖 10 格全亮 |
| 5 | Ardot 13–17 号板不废弃也不删除 | 原样保留，本轮零改动 |
| 6 | 早/午/晚/夜宵要生成图标，要大众一眼看懂，但不能难看 | 4 张实拍餐食照片，见餐次图标板 |

## 2. 去重口径：18 个模板 key → 18 张图（14 器具 + 4 餐次）

`vesselTpl` 共 18 个 key。**形状重复的合并为一张通用图**，靠缩放/数量区分档位：

| 通用图 | 覆盖的 vesselTpl key | 表达档位的方式 |

| `mug` 马克杯 | `mug` | 单档 300 ml |
| `glass` 直身水杯 | `glass` | 单档 250 ml |
| `glass_wine` 高脚杯 | `glass_wine` | 单档 150 ml |
| `shot` 烈酒杯 | `shot` | 单档 50 ml |

| `bowl` 白瓷大碗 | `bowl_rice` / `bowl_noodle` / `bowl_soup` | 缩放：150 / 200 / 300 g |
| `plate` 白瓷圆盘 | `plate` | 缩放：半份 / 一份 / 两份 |
| `weight` 天平砝码 | `pot` | **数量**：×1 / ×2 / ×3（400/700/1000 g） |
| `bag` 包装袋 | `bag` | 缩放：小包 50 / 大包 100 g |

| `meal_night` 夜宵 | 餐次选择器 | 单图 |

**三处合并**：① `cup` 系 3 个 key 共用一张（奶茶/咖啡/汽水都是同一个大众杯型）；② `bowl` 系 3 个 key 共用一张（米饭/面条/汤都是同一个白瓷碗）。
**两处不用原物**：③ `pot` 用砝码代替锅（锅的份量没有大众通识，砝码有）；④ `piece`/`slice` 用白瓷球/方片代替「一个/一片」（这两个单位本身没有固定实物，用最中性的白瓷物件表达，实拍风、非图标）。

## 3. 份量的视觉换算规则（v3.1 调大版）

档位图的显示尺寸由 `amount` 推出，**同一张图靠缩放表达大小**。首版（倍率 6.08/9.5）杯类只有 22–28px 宽、
三档几乎看不出差别，v3.1 调大并加高分量卡：

- 分量卡加高：3 档 105×100 → **105×120**，2 档 160×112 → **160×120**，图区可用高 88px
- 高度 `h ∝ ∛(amount)`：`R≥1`（竖长器物）倍率 **9.0**；`R<1`（扁平器物）倍率 **13.0**；再夹到最大盒
- 宽高比沿用源图真实比例 `R = h/w`，不拉伸
- **计数类（1个/1片/1串，amount=1）不参与立方根缩放**，固定高 66px；单档弹窗里另放一张 150px 高的大图
- 砝码卡（`pot`）例外：固定 `ih = 26px`（105px 卡里放 3 个已接近宽度上限），`n` 个砝码横向排布、间距 3px

实测效果（弹窗①）：三档杯 33/37/42px 宽、63/71/80px 高，肉眼可辨。

## 4. 奶茶甜度：10 格电量条

- 10 个矩形格，格宽 3.6、间距 1.0、条高 13，总宽 ≈45px
- 亮格 `#2CC79A`，暗格 `#E2F4EC`
- 档位：无糖 0 / 三分糖 3 / 五分糖 5 / 七分糖 7 / 全糖 10
- 选中卡：底 `#EAF9F2` + `#2CC79A` 描边

## 5. 素材生成要点（踩坑记录）

1. **白瓷器具必须配浅灰背景**：纯白碗/盘/球/片放在纯白背景上，模型会把器物内部也填白，四角泛洪裁剪会漏进内部 → 这 4 个 key 的 prompt 改为 `on a very light grey seamless background`，让暖白器物比背景更亮，裁剪停在轮廓上。
2. **空器皿要反复强调 empty**：prompt 前置 `completely empty with nothing inside, no food, no liquid, no contents, no garnish`，否则模型会自行脑补装食物，破坏通用性。
3. **`plate`/`skewer` 不透明像素占比天然低**（29.7% / 10.5%）——扁盘和细签本来就只占画面一角，不是废图，判读时看不透明率而非文件大小。
4. **Pencil 单画板图片节点上限**：一块 1140×910 的板塞 ~28 个图片节点 → 导出**全空（0% 非白）**。拆成 ≤540px 宽、≤8 张图的 6 块小板后全部正常渲染。
5. **Pencil 渲染管线坑（v3.1 新增，最重要）**：当晚会话里 `Insert(parent, node)` 挂出来的**子节点全部不进渲染管线**——画板自身 fill 能渲染、`Get` 能读到节点、但截图/导出全白；且不是「1 帧延迟」，隔多次调用仍白。**唯一可靠通路：先 `Insert` 空壳 frame，再把整棵嵌套子树用 `Replace(id, {...壳属性, children:[...]})` 一次灌入**。两个前置坑：① `Update(id,{children})` 会报 `unexpected property "children"`（文档写「改 children 用 Replace」，实测 Update 偶尔能过但不可依赖）；② nodeData 里**叶子节点不能带空 `children: []`**，否则整棵树被拒——建树时给每个节点都挂了 children 数组的话，灌入前必须把空 children 递归 delete 掉。
