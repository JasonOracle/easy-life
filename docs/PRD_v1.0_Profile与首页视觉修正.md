> 版本归属：**v1.0**（Boss 明确「你现在做的都属于 v1.0，我们继续做」）
> 设计稿：Ardot `727289305476547`（首页 `3:22` / 添加食物 Sheet `3:144` / 个人中心 `3:573`）
> 本轮性质：**视觉修正**，不新增数据模型、不改存储结构。

## 1. Problem Statement

Boss 于 2026-09-20 01:58 一次性提出 5 个问题，全部经过截图圈点确认。它们不是 5 个孤立瑕疵，而是**同一条主线下的三个系统性缺失**：视觉层级（Hierarchy）、状态可辨识（Legibility）、样例完整性（Coverage）。

### 1.2 三个系统性缺失（这才是要解决的）

1. **层级塌陷**：P5b 是食物列表里「合计 / 明细」同权重；P1 是「头像 / 文字」同明度。**凡是并列的两个元素，必须至少有一个维度（尺寸 / 字重 / 颜色 / 边界）拉开可感知的差距。**
2. **状态不可辨**：P5a 是「空瓶」这个状态不可辨；P2 是「设置」这个语义在 17px 下不可辨。**图标与状态必须在最小渲染尺寸上做可辨识性验证，而不是在 4 倍放大图上确认。**
3. **样例不完整**：P4 暴露出 **UI 分支有两条（普通食物 / 特殊食物），设计稿只覆盖了一条**。凡是条件渲染分支（`opts` 为空 vs 非空、`vessel` 单档 vs 多档），**每一条分支都必须有设计样例**，否则该分支的实现质量无从验收。

### 1.3 情绪北极星

轻律生活的核心资产是「颜值」。但**颜值的下限不是「好看」，是「看得清」**——一个空瓶子看不出来的 App，再美的渐变也是负分。本轮的验收标准是：**把稿子缩到 50% 仍能一眼读出「这是什么、有多少、属于谁」。**

## 2. Architecture & Solution

### 2.1 设计原则订正（本轮新增，写入 design/VisualLanguage.md）

**原则 A · 边界优先于间距**：当两个并列元素的底色接近时，**先加边界（描边 / 投影 / 明度差）再考虑加间距**。单纯加大 gap 在浅色叠加场景下无效。

**原则 B · 最小尺寸可辨识**：所有图标必须在**实际渲染尺寸**（非放大图）下验证；线框类图标在 ≤20px 时层数不得超过 2 层，超过则改用**实心填充**。

**原则 C · 分支对等设计**：条件渲染的每一条分支都必须提供设计样例，写清该分支下「显示什么、不显示什么」。

**原则 D · 三级层级**：同一信息族（如热量）必须落在三个明确层级上——**合计（最大最深）/ 明细（次之）/ 辅助单位（最浅最小）**，相邻层级至少拉开两个维度。

### 2.2 逐项方案

#### P1 头像边界（Profile `3:587`）

- 头像 `3:588`：由 `fill: #FFFFFF / 无描边` 改为 **`fill: rgba(255,255,255,0.92)` + `stroke: rgba(255,255,255,1) 2px` + 薄荷投影 `0 6px 16px rgba(5,120,88,0.22)`**，让 62px 圆角方块在渐变上"立"起来。
- `AvatarRow 3:587`：`gap` 18 → **22**；`counterAxisAlignItems` 保持 `CENTER`。
- `NameCol 3:590`：`gap` 4 → **5**（姓名与副标题也拉开一档）。

#### P2 设置图标换实心齿轮（Profile SettingsBtn `31:25` / `31:29`）

- **弃用描边式 gear**，改用**实心齿轮路径**：外齿廓填充白色 `#FFFFFF`，中心挖一个 `r=3.2` 的孔（用 `fill-rule="evenodd"` 单条路径实现）。
- 图标尺寸 17 → **18**；容器 `31:25` 32×32 保持。
- 实心方案在 18px 下的可辨识度远高于描边方案（原则 B）。

#### P3 HeroWave 承载「目标提示」（Profile `3:601`）

- 按 Boss 选定方案：**放目标提示**，承接被删除的柱状图目标线信息。
- 文案：**`每日目标 1800 kcal · 今日还剩 530`**
  - 前半段把上一轮删掉的 `GoalLine/GoalTag` 承载的「每日目标」语义补回；
  - 后半段「今日还剩」与首页 `num-label`「还能吃」呼应（同一语义在两页说法一致）。
- 位置：`3:601` 中部偏下，水平居中；字号 **11px**，颜色 `rgba(10,79,61,0.62)`，字重 Regular。
- 数值来源：`goalStore.calorieGoal - foodStore.totalCal`。
- **注意**：文字必须落在曲线的**下方空腔区**（y≈30），避免与波形高光孔重叠。

#### P4 补普通食物设计样例（`3:144` 区域）

- **新增第 9 块画板**：`09 · 添加食物 Sheet（普通食物）`，x 坐标接在现有画板序列尾部。
- 样例食物：**白米饭**（`vessel: bowl_rice`，3 档分量，`opts` 为空）——覆盖「**无选项组**」这一从未设计的分支。
- 与奶茶样例对照，明确差异：
  | 区块 | 奶茶样例 | 普通食物样例 |
  |---|---|---|
  | 分量 | 小杯350 / 中杯500 / 大杯700（默认中杯） | 小碗150g / 中碗200g / 大碗300g（默认中碗） |
  | 选项组 | 甜度·估算（5 档）+ 加料（5 项多选） | **整块不渲染** |
  | 计算口径文案 | 「已按 中杯 500ml · 全糖 计算」 | 「已按 中碗 200g 计算」 |
  | 数量 | 1 份 | 1 份 |
- 同时补一个**按「个」计的样例**（水煮蛋，`vessel: piece`，单档），在稿面注文案标出「已按 1 个（约 50g）计算」——覆盖 `pieceWeight` 折算路径。
- **落地约束**：为控制画板数量，水煮蛋样例以**局部放大标注**形式贴在白米饭画板右侧，不单独占一整块 375 宽画板。

#### P5a 空瓶辨识度（`Bottle.uvue` + 设计稿 `3:41`）

- 按 Boss 选定方案：**加刻度线 + 强化轮廓**。
- 瓶身 `.body`：描边由 `rgba(255,255,255,0.9)` 改为 **`rgba(31,191,143,0.30)` 1.5px**（薄荷描边，与底色拉开明度差）；填充 `rgba(255,255,255,0.42)` → **`rgba(255,255,255,0.55)`**。
- 新增**刻度线 3 条**：位于内腔右侧，`left: 68px`，宽 10px、高 1.5px、圆角 1px、颜色 `rgba(31,191,143,0.35)`；y 分别为 33px / 66px / 99px（= 内腔高度 132 的 1/4、1/2、3/4 处），对应水位 25% / 50% / 75%。
- 空腹（`pct = 0`）时：瓶内无液体，但**刻度线与薄荷描边仍可见** → 瓶子形状与「水位为 0」这一状态同时可读。
- 设计稿侧：`3:41` BottleWrap 内同步补刻度线节点。

#### P5b 热量三级层级（首页 `3:79` / `3:95` 等）

- 按 Boss 选定方案：**加粗放大 + 深色**。
- 餐次合计（`MealCal 3:89` 等）：
  - 字号 `13.5` → **`15`**；字重 SemiBold `600` → **Bold `700`**；
  - 颜色 `#0A7A5C` → **`#0A4F3D`**（与餐次名称同色，形成「餐次标题行」整体）。
- 明细行热量（`FoodKcal-*`）：保持 `12.5px SemiBold #0A7A5C`。
- 收敛后的三级层级：

  | 层级 | 元素 | 字号 | 字重 | 颜色 |
  |---|---|---|---|---|
  | L1 合计 | 餐次右侧热量 `420 kcal` | 15 | 700 | `#0A4F3D` |
  | L2 明细 | 单条食物热量 `150 kcal` | 12.5 | 600 | `#0A7A5C` |
  | L3 辅助 | 时间 `07:30:12` / 份量 `40g` | 11 / 11.5 | 400 | `#A9BAB3` |

- 相邻层级各拉开 **3 个维度**（字号 +3.5 / 字重 +100 / 颜色跨 2 级明度），远超原则 D 的「至少两个维度」要求。

### 2.3 不做的事（明确边界）

- **不新增数据模型**：不引入 `history: {ts, value}[]`（列 v1.2）。
- **不加数量步进器**（Boss 已拍板：同一食物多次添加，靠首页自身时分秒区分）。
- **不恢复柱状图目标线**（Boss 已拍板：v1.0 靠本周概览七个水滴承载目标信息）。
- **不做「查看全部 30 天」页面**（本版本无此页）。

## 3. Acceptance Criteria (AC)

### AC-1 头像与文字边界
- [ ] Given 个人中心页面已渲染 When 观察 hero 区头像 `3:588` Then 头像具有可见的薄荷投影与描边，且其右边缘与「老刘」文字左边缘的水平间距 ≥ 22px
- [ ] Given 头像底色与 hero 渐变底色的明度接近 When 将截图缩小至 50% Then 头像轮廓仍可被清晰识别为一个独立圆角方块

### AC-2 设置图标可辨识
- [ ] Given 设置按钮渲染尺寸为 32×32、图标 18×18 When 观察图标内部 Then 齿轮为**实心白色填充 + 中心圆孔**，不存在三层以上描边线框
- [ ] Given 图标以实际渲染尺寸（非放大图）查看 When 询问「这是什么图标」Then 应被识别为「设置」，不应被识别为「太阳」「主题切换」

### AC-3 HeroWave 目标提示
- [ ] Given 个人中心 hero 区已渲染 When 观察波浪带中部 Then 显示文案「每日目标 1800 kcal · 今日还剩 530」，字号 11px，颜色 `rgba(10,79,61,0.62)`
- [ ] Given 当日摄入变化 When `foodStore.totalCal` 更新 Then 文案中的「还剩」数值同步更新为 `calorieGoal - totalCal`

### AC-4 普通食物设计样例
- [ ] Given Ardot 设计文件已打开 When 浏览画板列表 Then 存在一块标题含「普通食物」的添加食物 Sheet 画板
- [ ] Given 打开该普通食物样例 When 观察区块构成 Then 仅包含「分量 / 餐次」两段，**不含任何选项组区块**
- [ ] Given 该样例为按「个」计的食物 When 观察计算口径文案 Then 显示「已按 1 个（约 50g）计算」形式的克重折算说明

### AC-5 空瓶辨识度
- [ ] Given 首页水位为 0（空瓶）When 观察瓶子 Then 瓶身具有薄荷色描边与 3 条刻度线，瓶子轮廓清晰可辨
- [ ] Given 水位为 0 When 与页面底色对比 Then 瓶身轮廓与底色之间存在可感知的明度差，不出现「看不见瓶子」的情况

### AC-6 热量三级层级
- [ ] Given 首页餐次行已渲染 When 对比餐次合计热量与明细行热量 Then 前者字号 15px / 字重 700 / 颜色 `#0A4F3D`，后者字号 12.5px / 字重 600 / 颜色 `#0A7A5C`
- [ ] Given 两者并列显示 When 于 3 秒内扫视该餐次 When 应能立刻区分出「这一餐合计」与「单条食物」
- [ ] Given 明细行的时间与份量文本 When 与热量文本对比 Then 时间/份量颜色为 `#A9BAB3`，明度明显低于同行的热量文本

## 4. Testing Strategy

### 4.1 设计稿验收（Ardot）
逐项对照 AC-1 ~ AC-6 提审节点截图，**必须使用实际渲染尺寸查看**，禁止用放大图判定图标可辨识度（这是 P2 翻车的直接原因）。特别验证：AC-2 的齿轮图标需在 1× 缩放下做「盲认测试」（不告知答案，看能否识别为设置）。

### 4.2 App 端验收
- 微信开发者工具 + 真机各跑一遍首页与个人中心。
- 空瓶场景构造：清空当日记录（`foodStore.clearToday()`）后观察瓶子。
- 双重添加场景：连续添加两次「鸡蛋」，确认首页出现两行且各自带独立 `HH:MM:SS`。

### 4.3 边界与回归
- **回归红线**：`Bottle.uvue` 改动不得影响正常水位（pct=0.5 / pct=1.0）与超标态（`over=true` 珊瑚色）的渲染。
- **回归红线**：`Profile.uvue` 与 `Home.uvue` 的改动不得触碰上一轮已修的两处 P0（`pieceWeight` 折算、`optTpl` 选项渲染）。
- **层级回归**：把首页缩至 50% 截一张图，验证 AC-6 的三级层级仍成立。
- **数值一致性**：Profile 波浪文案的「还剩」数值必须与首页 `num-value` 同源同值。

### 4.4 已知限制
- HeroWave 文案写死「每日目标 1800」时，若 Boss 后续修改目标值，需同步 `goalStore.calorieGoal`——本轮为设计稿演示值。
- 普通食物样例仅覆盖两条分支（`bowl_rice` 三档 / `piece` 单档）；`opts` 为空的其余 vessel 类型（`bottle` / `can` / `pot` 等）沿用同一渲染逻辑，不单独出样例。
